# Lessons

- Optimize repeated reviewer launches before reducing independent discovery
  breadth. Held-out results show that four simplicity seats recover findings a
  single seat misses.
- Keep the root-cause plan gate, but run it once per material fix cycle. Removing
  it recreates partial fixes and later review churn.
- Never append a cumulative findings ledger to every reviewer prompt. Supply a
  concise decision digest and immutable plan snapshot instead.
- Do not use instructions that declare time or token use unlimited. Give each
  reviewer a bounded evidence workflow and a clear completion condition.
- Verify the rendered roster before probing. Configuration keys that are present
  but unsupported fail open to auto-detected models and silently violate the
  requested panel.
- Keep explicit numeric review schedules as a separate compatibility contract.
  Adaptive defaults can change without making `/rev 8` ambiguous.
- Use a distinct plan-panel label when artifact names derive from the round label.
  Reusing the code round label silently overwrites its prompt.
- Count successful reviewer results separately from provider usage. A completed
  seat can expose no usage, while one seat can make several billed retry calls.
- Preserve raw usage before every adapter call, including a second process with
  the same seat and round. Fixed stream paths otherwise erase the expensive try.
- A four-bundle verification contract needs four valid bundle results even when
  the panel has only three seats or one bundle owner fails.
- Static contract tests must plant the content they forbid and exercise helper
  flags. A filename grep or ignored fourth argument can pass without protection.
- Canonicalize artifact paths in prompt tests and assert the full source line.
  Logical `/tmp` aliases can otherwise make both positive and negative checks
  pass against different path spellings.
- Treat a reviewer result as completed only when the finding schema validates
  and its recorded exit is successful. Meter failed attempts independently so
  optimization data does not hide paid failures.
- Enforce explicit positive seat counts before padding. A runnable fallback
  panel does not satisfy an exact reviewer configuration.
- Store live transcript state by seat name. A scalar transcript field cannot
  distinguish repeated seats from the same provider.
- State each adaptive schedule rule once in both host skills, then contract-test
  the exact wording. Duplicate prose had allowed the plan trigger and
  verification timing to contradict themselves.
- A compatibility fallback needs an explicit artifact boundary. A session-wide
  version bit would either reject old receiptless results or accept a crashed
  same-label relaunch; filename plus content hash preserves only the exact old
  artifact.
- When one status code covers permanent configuration and retryable availability,
  bounded waiting becomes repeated waste. Classify the root cause once and let
  stack orchestration fail fast only on the permanent class.
- A numeric minimum is incomplete without its continuation and termination rules.
  Preserve each host's complete legacy contract, including its own lens table,
  when adaptive defaults are introduced beside it.
- Every status-producing launch must write its exact artifact label and seat list
  together. Reusing a session-wide seat list makes plans, extras, and one-seat
  repairs appear pending or invisible.
- A classified status is useful only if every wrapper preserves it. Test the public
  entry point's exit code, not only the producer and its message text.
- Reject permanent configuration before paid health probes. A failure that time
  cannot clear should not spend provider calls while proving it cannot run.
- Every negative configuration test needs a positive control that reaches the
  guarded operation. An empty roster can make a zero-probe assertion pass before
  the optimization exists.
- Remove the previous same-label artifact before validating a rerender. Atomic
  replacement alone preserves stale instructions when the new render fails.
- When shell test files share one process, reject duplicate function names before
  sourcing can silently replace coverage.
- When presenting optional optimizations, separate the recommended low-risk set
  from ideas that trade away review quality. A later instruction to apply all ideas
  should have an unambiguous scope without needing the user to restate the list.
- Exercise bounded-read audits against each provider's real shell envelope and turn
  shape. A correct inner command still fails if validation sees the wrapper first,
  while unknown call shapes must fail closed rather than certify zero evidence.
- A compact evidence artifact needs byte limits as well as row limits. One minified
  source line can otherwise erase the savings while satisfying the row-count test.
- Treat orchestration reports as fresh terminal receipts: nonempty regular files,
  no symlinks, and a state transition produced by the same attempt.
- Name the baseline and metric with every savings estimate. Reviewer-launch count,
  prompt words, and total provider-processed tokens are different denominators; a
  best-case launch ratio must never be reported as an end-to-end token reduction.
