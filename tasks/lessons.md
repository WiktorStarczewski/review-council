# Lessons

- Optimize repeated reviewer launches before reducing independent discovery
  breadth. Held-out results show that four simplicity seats recover findings a
  single seat misses.
- Keep the root-cause plan gate, but run it once per material fix cycle. Removing
  it recreates partial fixes and later review churn.
- Never append a cumulative findings ledger to every reviewer prompt. Supply a
  concise decision digest and immutable plan snapshot instead.
- Do not use instructions that declare time or token use unlimited. Give each
  reviewer a bounded evidence workflow and a clear completion condition.
- Verify the rendered roster before probing. Configuration keys that are present
  but unsupported fail open to auto-detected models and silently violate the
  requested panel.
- Keep explicit numeric review schedules as a separate compatibility contract.
  Adaptive defaults can change without making `/rev 8` ambiguous.
- Use a distinct plan-panel label when artifact names derive from the round label.
  Reusing the code round label silently overwrites its prompt.
- Count successful reviewer results separately from provider usage. A completed
  seat can expose no usage, while one seat can make several billed retry calls.
- Preserve raw usage before every adapter call, including a second process with
  the same seat and round. Fixed stream paths otherwise erase the expensive try.
- A four-bundle verification contract needs four valid bundle results even when
  the panel has only three seats or one bundle owner fails.
- Static contract tests must plant the content they forbid and exercise helper
  flags. A filename grep or ignored fourth argument can pass without protection.
- Canonicalize artifact paths in prompt tests and assert the full source line.
  Logical `/tmp` aliases can otherwise make both positive and negative checks
  pass against different path spellings.
- Treat a reviewer result as completed only when the finding schema validates
  and its recorded exit is successful. Meter failed attempts independently so
  optimization data does not hide paid failures.
- Enforce explicit positive seat counts before padding. A runnable fallback
  panel does not satisfy an exact reviewer configuration.
- Store live transcript state by seat name. A scalar transcript field cannot
  distinguish repeated seats from the same provider.
- State each adaptive schedule rule once in both host skills, then contract-test
  the exact wording. Duplicate prose had allowed the plan trigger and
  verification timing to contradict themselves.
- A compatibility fallback needs an explicit artifact boundary. A session-wide
  version bit would either reject old receiptless results or accept a crashed
  same-label relaunch; filename plus content hash preserves only the exact old
  artifact.
- When one status code covers permanent configuration and retryable availability,
  bounded waiting becomes repeated waste. Classify the root cause once and let
  stack orchestration fail fast only on the permanent class.
- A numeric minimum is incomplete without its continuation and termination rules.
  Preserve each host's complete legacy contract, including its own lens table,
  when adaptive defaults are introduced beside it.
- Every status-producing launch must write its exact artifact label and seat list
  together. Reusing a session-wide seat list makes plans, extras, and one-seat
  repairs appear pending or invisible.
- A classified status is useful only if every wrapper preserves it. Test the public
  entry point's exit code, not only the producer and its message text.
- Reject permanent configuration before paid health probes. A failure that time
  cannot clear should not spend provider calls while proving it cannot run.
- Every negative configuration test needs a positive control that reaches the
  guarded operation. An empty roster can make a zero-probe assertion pass before
  the optimization exists.
- Remove the previous same-label artifact before validating a rerender. Atomic
  replacement alone preserves stale instructions when the new render fails.
- When shell test files share one process, reject duplicate function names before
  sourcing can silently replace coverage.
- When presenting optional optimizations, separate the recommended low-risk set
  from ideas that trade away review quality. A later instruction to apply all ideas
  should have an unambiguous scope without needing the user to restate the list.
- Exercise bounded-read audits against each provider's real shell envelope and turn
  shape. A correct inner command still fails if validation sees the wrapper first,
  while unknown call shapes must fail closed rather than certify zero evidence.
- A compact evidence artifact needs byte limits as well as row limits. One minified
  source line can otherwise erase the savings while satisfying the row-count test.
- Treat orchestration reports as fresh terminal receipts: nonempty regular files,
  no symlinks, and a state transition produced by the same attempt.
- Name the baseline and metric with every savings estimate. Reviewer-launch count,
  prompt words, and total provider-processed tokens are different denominators; a
  best-case launch ratio must never be reported as an end-to-end token reduction.
- Treat a requested checkpoint push as an intermediate milestone when the user has
  already authorized an autonomous continuation. Push the reviewable state, report
  the exact commit, and resume the remaining loop without interpreting the push as
  a stop condition.
- Derive batching claims from transcript fields the real provider emits. A synthetic
  turn identifier can make an over-batch test pass while the production audit cannot
  observe the same boundary.
- Render required proof with each adapter's native read mechanism. If an external guard
  rejects an equivalent shell recipe, automatically switch to a hash-bound session
  artifact and validate its bytes before spending another reviewer call.
- Timestamp every savings estimate with its exact checkpoint and keep already-counted
  projected gains separate from new measured progress. Correctness hardening can make an
  optimization usable without increasing its headline reduction.
- Certification must measure accepted audited results, not only smaller prompts. A normal
  bounded search or harmless failed lookup that invalidates an otherwise complete seat can
  turn prompt savings into a whole-panel retry multiplier.
- Capture each provider's real hook response before implementing its parser. A synthetic
  string fixture can validate the wrong transport shape while every live read fails closed.
- Start every negative mutation from a fixture that first passes the complete validator,
  then pin the intended failure reason. Otherwise an earlier defect can make the test vacuous.
- Optimize certification for valid first-pass receipts before adding more evidence machinery.
  A smaller prompt that needs whole-panel retries can consume more tokens and hours than the
  original workflow. Measure elapsed time by phase and treat transport-invalid reviewer work as
  the first wall-time target.
- Keep authoring instructions and strict parsers on one executable contract. If the skill forbids
  a flag that preparation requires, the optimized path silently becomes its expensive fallback.
- Test orchestration examples as complete state transitions. Checking that `--replacement` appears
  somewhere did not prove the host appended it before composite verification.
- A replay gate earns its name only when its selected tests consume the preserved provider
  envelopes it hashes. Hashing an unused fixture cannot prevent a paid transport failure.
- Do not make an integrity failure advisory by code name alone. First prove that the exact
  call supplied no assigned patch, required source, plan, or citation evidence; duplicate,
  reordered, or oversized proof remains fatal.
- Discover shard tests from functions Bash actually loaded. Lexical function scans also see
  test-shaped fixture heredocs and try to execute commands that were never defined.
- Preserve historical measurement rosters as part of the baseline. After a model mix changes,
  compare prompt size, evidence bytes, proof calls, tool turns, retries, and local suite time
  directly; label provider tokens, cost, elapsed time, and finding yield with the new roster
  instead of attributing their difference to workflow changes alone.
- Read-only tool restrictions do not neutralize a provider's planning-mode system prompt. If the
  transport asks a reviewer to plan, it can override the evidence-first protocol and waste a full
  paid attempt. Keep read-only enforcement in the tool allowlist and guard while using a neutral
  execution mode.
- A final transcript audit prevents false certification but does not prevent wasted provider work.
  Fix deterministic hook false positives and prompt conflicts before adding a stateful live phase
  machine; add the phase machine only if a live canary still violates evidence order.
- Parallel test shards need separate system temporary directories as well as separate fixture roots.
  Helpers that sweep stale global leases can otherwise delete another shard's live resources.
- Bind replay receipts to both reviewed bytes and the active model-effort roster. A cached transport
  contract for a different reviewer mix does not prove the configuration being launched.
- A rendered provider error string is not proof that a tool never executed. Require the provider's
  matching nonexecution metadata before omitting a failed call from evidence and missing-output checks.
- A positive probe control must use one recorder or independent recorder files. Parallel provider shims
  that truncate one shared argument file make the control nondeterministic even when the product is correct.
- A provider can follow the first-read rule and still waste a paid attempt on the next artifact. Canary the
  complete patch, packet, segment, index, and source sequence, and state that order once without competing cues.
- A prompt rule cannot prevent a model from calling an exposed tool. If one forbidden call permanently invalidates
  the receipt, either remove that tool for the phase or end the provider session on the first fatal hook decision.
- Assert the exact seat, adapter, model, and effort rows immediately before every paid panel. A misspelled config
  variable or omitted host selector can silently fall back to the installed roster and invalidate the measurement.
- Once a plan seat exhausts its exact retry, the remaining attempt cannot certify that plan label. Preserve completed
  siblings and partial streams, report the panel incomplete, and never widen the specialist to legacy full scope.
- A provider replacement applies to every future council surface unless the user limits it to one run. Remove the
  retired provider from live discovery, launch, examples, and tests while preserving explicit historical roster labels.
- Plan specialists should compare their cluster against the last compatible certified code snapshot. Keep one full-state
  completeness seat, but do not make every plan lens reread cumulative code that was already certified and did not change.
- Parallel verification should schedule exact test identities by measured critical-path cost. Preserve every assertion,
  isolate process-control shards, and make stale cost hints affect order only so scheduling cannot weaken selection.
- A live-abort mechanism earns its complexity only when its panel-wide savings clear the optimization threshold after
  deterministic prompt and audit failures are fixed. A large saving inside one failed seat can still be a sub-10-percent
  saving for the full council.
- A reviewer task needs a compiled input contract, not a broad repository instruction. Give specialists only their
  receipt-relative delta and proof closure, reject accidental full-patch or cluster-less assignments before launch, and
  keep one explicit completeness seat for the cumulative state.
- Bounded inputs do not guarantee a usable result if navigation can consume the whole run. Reserve final-response
  capacity after assigned proof is complete and treat a missing result schema as a seat-local failure that preserves
  valid siblings.
- A hand-built review prompt is executable policy. Parse it with the production authorization function before launch
  and prove every assigned session artifact is authorized; a human-readable scope bullet with the wrong heading can
  make every seat unable to read its target while still consuming provider time.
- Tell a review seat which native first read to make. A tiny prompt can still fail immediately when the model combines
  hash, count, and search commands into one shell call that violates the auditor's pure-read contract.
- Schema-specific transcript checks must treat an absent evidence manifest as an ordinary legacy panel. Guard the
  schema boundary before dereferencing manifest fields so full-scope compatibility cannot crash the auditor.
- Reconstruct seat order from `roster.json`, never JSON object key order. A provider rename can change lexical order
  while the launch and bundle assignment contract remains stable.
- A mandatory first action must appear before every competing task in the rendered prompt, not merely somewhere in it.
  Bind that exact instruction and its precedence before launch, then recheck the exact artifact set after the run so a
  mutated prompt cannot widen a specialist while retaining a valid manifest.
- A denied-call regression must prove the provider-specific nonexecution branch actually ran. Use the exact hook-error
  envelope and metadata, assert the attempt still affects first-call policy, and separately assert it is absent from
  completed tool-call accounting.
- A frozen read-only source tree exposes hidden fixture assumptions. Builders and tests may copy 0444 or 0555 files into
  private staging areas and then rewrite them. Add owner-write only to the private copy, preserve source modes, and run
  the whole gate from the frozen tree before treating focused results as certification.
- Once the user freezes an optimization release, treat scope as closed. Fix only failures required for the current
  contract, record optional ideas for later, and drive directly through certification, release, and installation.
- A child-process registry does not own a process until launch and registration are one signal-safe operation. Block
  termination signals through that window, then let the handler clean the registered process group.
- Never turn a failed provider-version probe into a reusable cache value. Missing, unavailable, empty, and nonzero
  version results must stop contract replay before cache lookup or receipt publication.
- Put packet batching limits into both the manifest and the reviewer's exact next action. A general byte cap does not
  stop a model from combining individually valid packets into one audit-invalid tool turn.
- Audit metadata can be exhaustive without printing every identity into the paid prompt. Render the smallest
  deterministic obligation that satisfies the audit, keep the complete set in the signed manifest, and measure the
  real compiled prompt before launch.
- Keep partitioning, validation, rendered instructions, and operator docs on one byte-limit contract. A unit test of
  the partitioner cannot prove that its newly accepted artifact survives end-to-end manifest verification.
- Every exposed reviewer tool needs a transcript parser, hook, and receipt path before release. A read-only tool can
  still invalidate a paid seat when the auditor does not recognize its events, so remove unused tools from the surface.
- A completion budget counts attempted repository expansion after proven nonexecution filtering, including failed calls.
  Counting only successful output lets repeated stale-path reads consume the response window without tripping the cap.
- Provider-contract identities bind execution-relevant metadata as well as bytes. A chmod-only change to a script must
  invalidate the receipt even when its content hash is unchanged.
- Provider quota degradation should be explicit, temporary, and visible in the roster identity. Replace unavailable
  preferred seats only for quota or capacity failures, restart one frozen panel as a whole, and probe the preferred
  providers again on the next run so an exhausted account cannot silently become a permanent roster change.
- A small late release requirement should reuse the active plan and certification when its behavior is covered by the
  same roster, runner, profile, and integration gates. Do not create a second full certification campaign unless it
  changes the review contract beyond those existing boundaries.
- During release convergence, record low-impact follow-up hardening for the next release instead of expanding the blocker
  set. Keep fixing P0-P2 findings and preserve meaningful focused and integration verification. If a reviewer labels a
  behavior bug P3, preserve the task but do not broaden the executable P3 definition beyond style, naming, or comments.
- A detailed documentation rewrite requested during certification does not need another paid review panel when the user
  explicitly excludes it. Self-check links, structure, examples, and local validation, then keep code certification focused.
- An inclusive search-result cap needs one extra observable record. If a command truncates at the accepted maximum, exact
  capacity and overflow are indistinguishable. Read through the sentinel, accept the maximum, and reject the sentinel.
- Call a replacement seat a receipt or coverage repair in status updates. Calling it simply a repair makes it sound like
  repository code is changing while the tree is actually frozen.
- When a final self-host panel has no valid predecessor receipt, say that its scope must widen before launch. Once it seals,
  constrain any post-fix verification to the receipt-relative delta plus the one required full-state integration seat.
- When CI fixtures execute a system binary, install that binary explicitly in every runner image. A developer-machine pass
  does not prove a clean hosted runner has the same tool inventory, so reproduce missing-tool failures in a clean container.
- A fail-closed gate must still expose the failing shard in hosted CI. Print the bounded tail of nonzero private logs, and
  avoid duplicate push and pull-request matrices for the same feature commit, so one failure produces one useful diagnosis.
